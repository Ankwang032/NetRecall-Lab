# Notion 개념 소스

Notion 노트를 NetRecall Lab에 넣는 방법은 두 가지입니다.

| 방법 | 대상 | 원본 | AI |
|---|---|---|---|
| **가져오기** | 일반 페이지 (하위 페이지를 골라서) | 가져온 뒤에는 .md 파일이 원본입니다 | 씁니다. 형식을 맞출 때 메타데이터를 채웁니다 ([형식이 다른 노트 맞추기](markdown-concept-format.md#형식이-다른-노트-맞추기)) |
| **동기화** | 데이터베이스 하나. 행 하나가 개념 하나 | Notion 행이 원본입니다 | 쓰지 않습니다. 동기화할 때마다 결과가 같아야 질문과 카드가 흔들리지 않습니다 |

같은 노트를 두 방법으로 동시에 쓰지 마세요. 개념 ID가 겹쳐 충돌로 보고됩니다.

## 설정

| 환경변수 | 내용 |
|---|---|
| `NOTION_TOKEN` | Notion 통합(integration) 토큰. 없으면 Notion API가 503입니다 |
| `NETRECALL_NOTION_DATABASE` | 동기화할 데이터베이스의 주소나 id. 없으면 동기화 버튼이 Notion을 건너뜁니다 |

- 앱은 Notion을 읽기만 합니다.
- 읽을 페이지·데이터베이스의 **연결(Connections)**에 통합을 추가해야 합니다. 추가하지 않으면 "페이지를 찾지 못했습니다"가 나옵니다.
- API: `GET /notion/pages`, `POST /notion/files` (가져오기), `POST /sync/notion` (동기화, `?dry_run=true`로 미리보기)

## 동기화: 데이터베이스 속성

| 속성 이름 | Notion 유형 | 필수 | 개념 필드 | 규칙 |
|---|---|---|---|---|
| 이름 | 제목 | 필수 | `title` | 페이지 아이콘은 제목에 들어가지 않습니다 |
| 개념 ID | 텍스트 | 필수 | `id` | 대문자 접두사, `-`, 숫자 3자리 이상 (예: `NET-111`). 정한 뒤에는 바꾸지 마세요. 바꾸면 다른 개념이 되어 복습 이력이 이어지지 않습니다 |
| 카테고리 | 선택 | 선택 | `category` | |
| 키워드 | 다중 선택 | 선택 | `keywords` | |
| 난이도 | 숫자 | 선택 | `difficulty` | 1~5 정수 |
| 선수 개념 | 관계형 (같은 데이터베이스) | 선택 | `prerequisites` | 연결한 행의 개념 ID로 바꿔 저장합니다 |
| 연관 개념 | 관계형 (같은 데이터베이스) | 선택 | `related` | 선수 개념과 같습니다 |
| 실습 | 다중 선택 | 선택 | `labs` | `LAB-` 뒤에 숫자 3자리 이상 (예: `LAB-002`) |

- 속성은 **이름**으로 찾습니다. 이름이 다르면 없는 속성으로 봅니다. 선택 속성은 빈 값이 되고, 이름·개념 ID가 없으면 그 행은 오류입니다.
- 유형이 표와 다르면 그 행은 오류입니다 (예: 난이도를 선택 속성으로 만든 경우).
- 표에 없는 속성은 읽지 않습니다. 학습 상태 같은 개인 속성을 자유롭게 둘 수 있습니다. Markdown frontmatter가 모르는 키를 오류로 보는 것과 다릅니다.
- 자기 자신을 선수·연관 개념으로 연결하면 오류입니다.
- 연결한 행에 개념 ID가 없거나 읽지 못하면 그 연결만 빼고 경고합니다.
- 데이터 소스가 여러 개인 데이터베이스는 동기화할 수 없습니다.

## 동기화: 본문과 질문

- 페이지 Markdown(`GET /v1/pages/{id}/markdown`, `markdown_version=v2`)을 [형식 맞추기와 같은 정리 규칙](markdown-concept-format.md#형식이-다른-노트-맞추기)으로 정리해 본문으로 씁니다.
- 질문은 `## 질문` 또는 `## 이해 확인 질문` 섹션에서 읽습니다. 토글은 첫 줄만 질문이고 안의 답은 버립니다. 섹션 전체를 본문에서 지웁니다.
- 중복을 뺀 질문이 **3개 이상**이어야 합니다. 질문 하나가 복습 카드 한 장입니다. 질문 문장을 고치면 새 카드가 됩니다.
- 본문이 비어 있으면 오류입니다. Notion이 페이지를 끝까지 돌려주지 못하면(`truncated`), 또는 내보내지 못한 블록이 있으면 경고합니다.

## 동기화 규칙

- `source_type`은 `notion`, `source_ref`는 페이지 ID입니다.
- 제목·본문·속성·질문이 그대로면 갱신하지 않습니다.
- 행을 휴지통으로 보내면 개념을 보관합니다. 복습 이력은 남고, 행을 되살리면 개념도 복구됩니다.
- 같은 개념 ID가 여러 행에 있으면 먼저 만든 행만 반영하고 나머지는 오류로 보고합니다.
- 행 하나를 읽지 못하면 그 행만 오류이고, 이미 저장된 개념은 보관하지 않고 유지합니다.
- 데이터베이스 자체를 읽지 못하면(연결 끊김, 권한 없음) 동기화 전체를 멈춥니다(502). 연결 문제로 모든 개념이 보관되면 안 되기 때문입니다.

## 노트를 다른 소스로 옮기기

다른 소스(Markdown 폴더)가 쓰는 개념 ID는 덮어쓰지 않고 충돌로 보고합니다. 다만 그 개념이 **보관된 상태**면 새 소스가 넘겨받습니다. 개념의 소스와 위치가 바뀌고 복습 카드와 이력은 이어집니다.

1. 원래 소스에서 노트를 지웁니다 (.md 파일 삭제, 또는 Notion 행을 휴지통으로).
2. 동기화합니다. 개념이 보관됩니다.
3. 새 소스에 같은 개념 ID로 노트를 넣고 다시 동기화합니다. 결과에 "넘겨받음"이 나옵니다.

동기화 버튼은 Markdown 폴더 → Notion 순서로 동기화합니다. Notion에서 .md로 옮길 때는 Notion 쪽 보관이 나중에 일어나므로, 첫 동기화에서 충돌이 보이면 한 번 더 누르세요.
